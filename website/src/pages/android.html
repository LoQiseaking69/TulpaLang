Features

A complete Tulpa workbench, sized for one hand.

Your phone is the device

phone::accel(), tilt(), pressure(), location() return unit-checked quantities. Vibration, torch, speech, tones and notifications are the actuators.

MuJoCo + 3D co-simulation

MuJoCo runs on the device. cosim::connect() programs drive a model in lock-step while an OpenGL ES view shows it live. Orbit, pinch, push, reset.

Touch-first editor

Highlighting, live diagnostics, completion (including module:: members), outline, go-to-definition, find/replace, undo and a symbol/unit key row.

Live instruments

tlm::plot charts, phone::gauge readouts, event markers and shareable artifacts while a program runs.

Machines & verification

Every machine drawn as a tappable graph. One tap fuzzes the file's contracts and shrinks failures to a minimal counterexample.

Learn by running

35 examples, including the full Morty humanoid stack, the Driver SDK, planning and Tulpa Link, and an in-app guide whose code blocks run with one tap.

Co-simulation

The same program on the desk and in the field.

Tulpa Field speaks HermiSim's co-simulation protocol. A program written against cosim:: runs unchanged on the phone's own MuJoCo model, or drives a desktop HermiSim over Wi-Fi.

  • HermiSim workspaces work as-isThe model comes from hermisim.json, then any MJCF .xml beside the program.
  • Morty on a phoneCapture-point balance, PINN, FPGA governor link and the behaviour machine, driving an 18-actuator humanoid.
  • Bring your own robotImport any MJCF model, then make a co-sim project for it from the model sheet.

Requirements & building

Android 8.0 (API 26) or newer on arm64, armv7 or x86_64, with OpenGL ES 3.0. No network access is needed, except for an optional remote co-simulator.

CI builds the Rust runtime and MuJoCo with the NDK, assembles the app, runs an emulator smoke test, and publishes a signed release whenever android/VERSION changes.
